# 订单详情页关联机器设计

## 目标

经理可以在已有订单的详情页直接添加或解除关联机器，不必再进入机器详情页操作。员工仍只能查看关联关系。

## 交互设计

订单详情页现有“关联机器”区域继续展示当前关联机器及其状态。

- 对经理：每台已关联机器右侧显示“解除关联”；区域底部显示“可关联机器”下拉框和“保存关联”按钮。
- 对员工：只展示关联机器列表，不显示添加或解除控件。
- 下拉框只列出当前工作区中尚未关联该订单的机器，并按机器编号排序。
- 每次添加一台机器，成功后返回当前订单详情页。
- 每次解除一台机器，成功后返回当前订单详情页。
- 没有可关联机器时显示说明文字，不显示空下拉框。
- 订单状态为“完成”时，所有用户都只能查看关联关系；页面明确提示完成订单不能调整机器关联。

采用单台添加/解除，而不是多选后整体覆盖。这样与机器详情页的现有操作一致，也避免一次保存意外解除多台机器。

## 服务与动作

继续复用 `linkMachineToOrder` 和 `unlinkMachineFromOrder` 服务，不新增数据表或迁移。

新增订单侧 Server Actions，接收 `orderId` 和 `machineId`：

- 动作使用 `requireManager` 强制经理权限，不能只依赖界面隐藏。
- 添加与解除分别调用现有服务函数。
- 成功后重新验证机器列表、对应机器详情、订单列表和当前订单详情。
- 成功后重定向回 `/orders/<orderId>`。

订单详情页并行读取订单摘要与工作区机器列表，从全部机器中排除已关联机器，生成“可关联机器”选项。服务层继续负责工作区隔离、实体存在性和完成订单不可新增关联的校验。

解除关联也必须在服务层拒绝完成订单，避免通过直接提交表单绕过页面锁定。该校验在现有事务内读取订单后执行，保证并发状态变化下仍然有效。

## 错误与边界

- 缺少订单或机器标识时返回明确错误。
- 非经理调用添加或解除动作时拒绝操作。
- 已完成订单不能添加或解除机器。
- 已关联机器不会出现在可选列表中。
- 重复添加继续由现有幂等关联服务处理。
- 解除不存在的关联继续返回“机器未关联该订单”。
- 机器和订单必须属于当前工作区，沿用现有服务校验。

## 测试

- Action 测试：经理可从订单侧添加和解除机器，正确重新验证路径并返回订单详情；员工被拒绝；缺少参数被拒绝。
- Service 测试：已完成订单不能解除机器，确保后端锁定完整。
- 页面测试：经理看到添加/解除控件和过滤后的可选机器；员工和完成订单看不到操作控件；无可选机器时显示说明。
- E2E：创建订单和两台机器，在订单详情页添加一台、解除一台，并确认页面关联列表与机器详情同步。

## 非目标

- 不提供多选后整体覆盖全部机器关联。
- 不改变新建订单时已有的多选机器功能。
- 不改变生产记录的目标订单选择流程。
- 不修改机器状态或机器基础信息。
